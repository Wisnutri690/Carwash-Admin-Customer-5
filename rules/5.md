# PROJECT 5 — APEX. CARWASH MANAGEMENT SYSTEM
## Technical Product Requirements Document (PRD) & Architecture

> **Version:** 1.0.0 (Approved & Synchronized with Midtrans)  
> **Backend Stack:** Express.js + Prisma ORM + PostgreSQL + Socket.IO  
> **Frontend Stack:** React 19 + TypeScript + Tailwind CSS v4 + Axios + Midtrans Snap SDK  
> **Payment Gateway:** Midtrans Snap (QRIS, VA BCA/Mandiri/BRI/BNI, GoPay) + Kasir Tunai  
> **Architecture:** Dual-Role (Customer Self-Service + Admin/Kasir Portal)  

---

# 1. Dual-Role Architecture & User Journey

### 🚗 Sisi Customer (Portal Mandiri - Mobile-First)
1. **Autentikasi Email**: Registrasi dan Login instan menggunakan email unik (tanpa password).
2. **Vehicle Self-Service**: Menambah, melihat, dan mengelola kendaraan milik customer sendiri.
3. **Booking Mandiri**: Membuat order cuci mandiri dengan proteksi anti-double booking pada mobil yang sedang aktif.
4. **Pembayaran Online Midtrans**: Bayar via Snap QRIS, Virtual Account (BCA/Mandiri/BRI/BNI), atau Bayar di Kasir.
5. **Live FIFO Queue Tracking**: Memantau posisi antrean (`queuePosition`), mobil di depan (`ahead`), dan estimasi waktu tunggu (`estimatedMinutes`) secara realtime via WebSocket.
6. **Riwayat & Pembatalan**: Melihat histori pesanan selesai (`COMPLETED`) dan membatalkan pesanan jika masih dalam status `WAITING`.

### ⚡ Sisi Admin / Kasir (Protected Access)
1. **Autentikasi Admin**: Login via email (`admin@carwash.com`) dan password terenkripsi bcrypt.
2. **Order Management**: Monitoring seluruh antrean, mengubah status order (`WAITING` ➔ `IN_PROGRESS` ➔ `COMPLETED` / `CANCELLED`), dan menugaskan staf cuci (`staffId`).
3. **Kasir & Billing**: Memproses pembayaran (`CASH`, `QRIS`, `TRANSFER`), mengubah status ke `PAID`, dan mencetak invoice digital.
4. **Master Data Management**: Mengelola Layanan (Services), Staf (8 staf: 7 aktif, 1 tidak aktif), Data Pelanggan, dan Kendaraan.

# 2. Status Enums & Business Logic

### Status Order (`OrderStatus`)
- `WAITING`: Order baru dibuat, masuk antrean FIFO. `staffId: null`, `adminId: null`.
- `IN_PROGRESS`: Mobil dipanggil masuk ke bay pencucian. Admin menugaskan `staffId`.
- `COMPLETED`: Mobil selesai dicuci. `completedAt` terisi otomatis.
- `CANCELLED`: Order dibatalkan oleh Customer (hanya saat `WAITING`) atau Admin.

### Status & Metode Pembayaran
- `paymentStatus`: `UNPAID` (Default booking) | `PAID` (Setelah pembayaran Midtrans / Kasir)
- `paymentMethod`: `QRIS` | `CASH` | `TRANSFER`

### Integrasi Midtrans Snap & Webhook
- **Request Snap Token**: `POST /api/payments/midtrans-token` dengan payload `{ orderId }` mengembalikan `snapToken` dan `redirectUrl` untuk popup Midtrans di frontend.
- **Webhook Callback**: `POST /api/payments/midtrans-webhook` menangani notifikasi server-to-server dari Midtrans saat pembayaran berhasil, otomatis mengubah `paymentStatus: "PAID"` dan menghasilkan Invoice.

### Logika Antrean FIFO & Estimasi Waktu
- `queuePosition`: Nomor urut antrean customer di antara order `WAITING` (berdasarkan `checkInTime` ASC).
- `ahead`: Total mobil di depan (jumlah mobil `IN_PROGRESS` + mobil `WAITING` sebelum order ini).
- `estimatedMinutes`: Akumulasi sisa durasi cuci mobil `IN_PROGRESS` + durasi mobil `WAITING` di depannya.

# 4. Pemetaan Lengkap REST API Backend (Source of Truth)

### 4.1 Autentikasi (`/api/auth`)
- `POST /api/auth/login`: Login Admin `{ email, password }` ➔ JWT `{ role: "ADMIN", id, email }`
- `POST /api/auth/customer/login`: Login Customer `{ email }` ➔ JWT `{ role: "CUSTOMER", id, email }`
- `POST /api/auth/customer/register`: Register Customer `{ name, email, phone }` ➔ JWT

### 4.2 Customer Vehicle Self-Service (`/api/customer/vehicles` - Customer Token)
- `GET /api/customer/vehicles`: Ambil semua mobil milik customer yang sedang login.
- `POST /api/customer/vehicles`: Tambah mobil baru `{ plateNumber, brand, model, color, year? }`.
- `DELETE /api/customer/vehicles/:id`: Hapus mobil (proteksi jika sedang ada antrean aktif).

### 4.3 Customer Orders & FIFO Tracking (`/api/customer/orders` - Customer Token)
- `POST /api/customer/orders`: Buat booking cuci `{ vehicleId, services: [{serviceId, quantity}], notes? }`.
- `GET /api/customer/orders/active`: Ambil antrean aktif customer + object `queueInfo` (FIFO calculation).
- `GET /api/customer/orders/history`: Ambil riwayat order selesai (`COMPLETED` / `CANCELLED`).
- `PATCH /api/customer/orders/:id/cancel`: Batalkan order mandiri (hanya jika masih `WAITING`).

### 4.4 Midtrans Payment Gateway (`/api/payments`)
- `POST /api/payments/midtrans-token`: Request Snap Token Midtrans `{ orderId }` ➔ `{ snapToken, redirectUrl }`.
- `POST /api/payments/midtrans-webhook`: Endpoint Webhook / Callback Midtrans untuk update `PAID` otomatis.

### 4.5 Admin Order Management (`/api/orders` - Admin Token)
- `GET /api/orders`: Ambil seluruh order di sistem carwash.
- `GET /api/orders/:id`: Detail order spesifik + invoice + vehicle + customer + orderItems.
- `POST /api/orders`: Admin membuat order langsung di kasir (walk-in).
- `PUT /api/orders/:id`: Admin update status order (`IN_PROGRESS` / `COMPLETED`) & assign `staffId`.
- `DELETE /api/orders/:id`: Hapus data order.
- `POST /api/orders/:id/pay`: Proses pembayaran kasir (ubah `PAID` & generate invoice).
- `GET /api/orders/:id/invoice`: Ambil data invoice resmi untuk dicetak/PDF.

### 4.6 Master Data Management (Admin Token)
- `/api/services`: CRUD Layanan & Durasi Cuci.
- `/api/staff`: CRUD Data Staf (8 staf: 7 aktif, 1 nonaktif).
- `/api/customers`: Admin customer management.
- `/api/vehicles`: Admin vehicle management.

# 5. Arsitektur WebSocket Realtime Tracking (Socket.IO)

1. **Prinsip Utama**: Database PostgreSQL & REST API adalah **Source of Truth**. WebSocket murni sebagai lapisan broadcast realtime event.
2. **Koneksi Tunggal**: Socket.IO terpasang pada Express HTTP server yang sama (Port 3000).
3. **Event Trigger**:
   - `ORDER_CREATED`: Dipancarkan saat ada booking baru masuk.
   - `ORDER_STATUS_UPDATED`: Dipancarkan saat Admin mengubah status (`WAITING` ➔ `IN_PROGRESS` ➔ `COMPLETED`).
   - `QUEUE_UPDATED`: Dipancarkan ke room customer terkait ketika posisi antrean/estimasi waktu bergeser.
4. **Resiliensi Reconnect**: Jika koneksi terputus lalu tersambung kembali, frontend melakukan *re-fetch* data aktual melalui REST API (`GET /api/customer/orders/active`), lalu melanjutkan mendengarkan event Socket.IO.
